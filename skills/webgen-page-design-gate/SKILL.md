# WebGen 页面设计执行门

## Overview
把页面设计流程从“会做页面”升级成“先定方向、再做实现、最后验证”的硬流程。
核心原则：**视觉方向未锁定，不进入最终页面实现；验证未完成，不得汇报完成或交付。**

## When to Use
适用于以下页面：
- landing page
- 品牌介绍页
- 产品介绍页
- 营销站
- 重设计页面
- 任何审美要求明显高于普通后台页/工具页的前端页面

不适用于：
- 纯后台配置页
- 内部工具页
- 单纯功能性占位页

## 执行总流程
固定执行顺序：

1. 信息收集
2. 方案确认
3. 视觉路线确认
4. 实现前自检
5. 页面实现
6. 构建/预览验证
7. 交付

**禁止跳步：**
- 未完成 2，不得进入 3/4/5
- 未完成 3，不得进入 4/5
- 未完成 4，不得进入 5
- 未完成 6，不得进入 7
- 未完成 6，不得宣称“已完成交付”

## Gate-01 信息收集门
进入方案前，必须完成以下信息收集：
- 页面类型与目标
- 目标用户
- 核心板块结构
- 是否品牌叙事 / 销售转化 / 作品展示
- 是否已有文案、图片、接口文档
- 是否允许占位文案
- 是否允许占位视觉
- 是否允许线上找图
- 适配目标：PC / Pad / H5
- 断点策略
- 触控热区策略
- Pad 横竖屏处理
- H5 首屏优先级
- hover 在触屏设备上的替代方式

必须写入 `DISCOVERY.md`。

## Gate-02 方案确认门
编码前必须先给出可确认方案，至少包含：
- 页面目标
- 页面结构
- Design Read
- DESIGN_VARIANCE / MOTION_INTENSITY / VISUAL_DENSITY
- 配色方向
- 字体方向
- 素材策略
- API 策略
- 响应式策略

只有用户或调度方明确表示：
- 可以
- 同意
- 按这个做
- 开始
- 确认方案

才允许继续。

未确认时：
- 只能继续澄清
- 只能迭代方案
- 不得写页面业务代码

## Gate-03 视觉路线确认门
凡是高审美页面，方案确认后、实现前，必须再做一次视觉方向锁定。

### 触发条件
满足任一项即触发：
- 品牌页
- 产品介绍页
- 营销站
- 重设计
- 用户强调“高级感 / 好看 / 品牌感 / 质感 / 审美”

### 必须双路线供选的场景
满足任一项时，**强制双路线**，不得单路线直接开工：
- 用户只给了很短的抽象需求，如“做个高级感页面”
- 没有真实图片 / 没有品牌视觉手册 / 没有参考站
- 页面目标偏品牌叙事而非单纯功能展示
- 首屏主视觉承担主要审美判断
- 当前项目属于重设计，且旧页面明显存在模板味

### 可单路线直做的场景
仅当同时满足以下条件时，才允许单路线：
- 用户明确说“按这个方向直接做”
- 已有明确参考风格或参考站
- 已有较清楚的素材、品牌调性或视觉锚点

### 输出要求

#### 策略 A：单一路线直做
可只输出 1 条视觉路线，但必须明确：
- 主视觉构图
- 页面气质关键词
- 禁止元素
- 信息密度
- 动效强度
- 为什么这条路线适合当前需求

#### 策略 B：双路线供选
默认推荐。至少给出 2 条明显不同的路线，例如：
- 编辑式器物陈列
- 广告海报式品牌叙事

每条路线必须写清：
- 主视觉方式
- 版式骨架
- 配色倾向
- 适合原因
- 风险点
- 哪类用户更可能喜欢

### 主视觉默认禁用清单
以下内容若无真实素材强支撑，默认禁止作为高端页主视觉：
- 廉价几何拼装假产品
- 明显 AI 感过强的伪 3D
- 紫蓝发光科技风
- 三等分功能卡片首屏
- 说明书式首屏
- 过多悬浮玻璃卡片
- 为了“高级感”堆满金色描边、重阴影、镜面反射特效
- 不贴题的抽象装饰大于产品本身

### 视觉路线落盘要求
视觉路线确认后，必须把以下内容写入 `DISCOVERY.md`：
- 最终路线名
- Design Read
- 三档位
- 主视觉构图说明
- 禁止元素
- 适配策略摘要

## Gate-04 实现前自检门
开始写页面前，必须逐项自检：
- [ ] `DISCOVERY.md` 已完整
- [ ] 方案已确认
- [ ] 视觉路线已确认
- [ ] 已写明主视觉构图
- [ ] 已写明禁止元素
- [ ] 已确定是单路线还是双路线选定结果
- [ ] 已明确首屏在 H5 的信息优先级
- [ ] 已明确真实素材不足时的退化方式

任一未满足，不进入实现。

## Gate-05 页面实现门
只有前 4 门通过后才允许进入实现。

实现时必须遵守：
- 页面主视觉先服务气质，再服务信息量
- 不得默认三等分功能卡片首屏
- 不得使用廉价玻璃、泛滥阴影、霓虹描边
- 必须补齐核心交互状态：
  - Loading
  - Empty
  - Error
  - Active Feedback
- 必须覆盖 `PC / Pad / H5`
- H5 不允许把核心信息藏进 hover
- 如无真实素材，不要硬拼假产品图；优先改为更稳的材质、排版、局部细节叙事

## Gate-06 验证门
页面写完后，不得直接汇报“完成”，必须先验证。

至少完成：
1. 文件结构检查
2. 静态资源引用检查
3. `pnpm install` 或等价依赖检查
4. `pnpm build` 或等价构建检查
5. 本地预览启动
6. 健康检查 / 地址可访问
7. 关键交互可运行
8. 响应式结构基本正确
9. 首屏视觉是否符合已确认路线

### 汇报规则
- 代码刚写完：只能说 `开发完成`
- 构建和预览通过后：才能说 `验证完成`
- 交付信息整理完：才能说 `交付完成`

禁止：
- 未 build 就说完成
- 未 preview 就说可交付
- 未验证交互就说页面可用
- 未对照已确认路线就说“设计已完成”

## Gate-07 交付门
交付前必须至少说明：
- 项目目录
- 关键实现文件
- 预览命令
- 构建命令
- 当前预览地址
- 已完成验证项
- 仍是占位的内容
- 后续若替换真实素材需要改哪些位置

## 审美失败回退规则
若用户明确反馈：
- 丑
- 不高级
- 没品牌感
- 太像模板
- 不是我想要的感觉

则必须立即回退到“视觉路线确认门”，而不是只做局部修补。

### 固定诊断输出模板
回退后必须输出：
1. 当前页面为什么失败（3~5 条）
2. 失败类型归类：
   - 主视觉失败
   - 版式气质失败
   - 信息密度失败
   - 配色材质失败
   - 模板味过重
3. 新的 Design Read
4. 新的三档位
5. 新视觉路线
6. 是否需要用户二选一确认

### 禁止的错误修复方式
- 只换颜色不改构图
- 只加阴影不改层级
- 只加动效掩盖版式问题
- 用户已明确说丑，仍坚持原路线小修小补

## 输出纪律门
在整个流程中，输出必须满足：
- 对外只说结论，不说内部过程噪音
- 不输出英文工作提示
- 不输出“Updating...”这类内部提示
- 不暴露过程性思维文本
- 阶段汇报必须使用简短中文结论

## Red Flags
出现以下任一情况，必须停止推进并回到上一步：
- 没有 Design Read 就开始写页面
- 没有视觉路线确认就开始做高审美页面
- 没有实现前自检就开始写页面
- 用假几何产品图充当高端主视觉
- 用户未确认方案就开始写业务代码
- build / preview 未完成就宣称已完成
- 输出过程中夹带英文过程说明或内部日志
- 用户已明确否定审美方向，仍继续在旧方向上修补

## Quick Reference
| 场景 | 必须动作 |
|---|---|
| 新品牌页 / 产品页 | 先 Discovery，再方案，再视觉路线确认 |
| 用户只说“做个好看的页面” | 强制双路线供选 |
| 无真实素材但要高级感 | 先锁路线，再选稳妥主视觉，不拼假产品图 |
| 用户说“先做一版” | 允许占位内容，但仍要先锁视觉方向 |
| 用户说“页面丑” | 回退到视觉路线确认门，不直接补丁修样式 |
| 页面代码已写完 | 先 build / preview / 检查，再汇报验证完成 |

## Common Mistakes
### 1. 结构正确但画面很丑
原因：先做信息结构，没做视觉路线锁定。
修正：高审美页面默认增加 Gate-03。

### 2. 主视觉廉价
原因：没有真实素材时误用假产品拼图。
修正：改为更抽象的材质海报，或更克制的编辑式排版。

### 3. 太早汇报完成
原因：把“代码写完”当成“任务完成”。
修正：严格区分开发完成 / 验证完成 / 交付完成。

### 4. 用户说丑后只微调
原因：把方向问题当成样式小问题。
修正：直接回退到视觉路线确认门，重锁方向。

### 5. 输出显得像 agent 在自言自语
原因：把内部工作提示暴露给用户。
修正：只保留阶段结论与必要说明。

## 执行口令
对高审美页面，默认心智改成：

**不是先做页面，而是先定视觉方向；不是代码写完就算完成，而是验证通过才算完成；用户一旦否定审美，就回退重定路线，而不是硬修旧稿。**
