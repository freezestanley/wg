# Discovery

## 页面目标

- 为大模型 / 企业 AI 品牌制作一页式中文宣传官网首版。
- 目标是在首屏 3 秒内说清楚：这不是纯概念模型，而是可以接入真实业务流程的企业级大模型方案。

## 目标用户

- 正在评估大模型落地的企业负责人、数字化负责人、产品负责人。
- 需要快速理解产品可信度、能力边界、场景价值与部署想象空间的中文受众。

## 页面结构

1. Hero：品牌主张、可信关键词、双 CTA、工作台视觉展示。
2. 核心能力：知识检索、工具调用、流程编排、人工接管。
3. 应用场景：客服、销售、运营三类真实业务场景。
4. 模型能力展示：可切换的 `Live / Loading / Empty / Error` 状态演示。
5. 客户 / 生态：集成系统与部署方式表达。
6. FAQ：回答品牌官网首版常见疑问。
7. CTA：引导用户补充品牌资产，进入正式官网定制。

## 风格方向

- 高级、科技感、可信、偏企业级产品品牌。
- 深色背景为主，采用克制的绿色 + 青色数据感点缀，不使用紫蓝霓虹 AI 套板风。
- 通过网格、内描边、弱玻璃材质与工作台式信息面板建立“可落地”的技术气质。

## Design Read

- 企业级大模型品牌官网，受众是中文 B 端决策者；风格语言偏深色系统界面、可信产品展示与轻量未来感，而不是概念化科幻海报。

## 设计拨盘

- `DESIGN_VARIANCE = 7`
- `MOTION_INTENSITY = 5`
- `VISUAL_DENSITY = 4`

## 合理假设

- 用户尚未提供真实品牌名、Logo、客户案例与部署架构图，因此先使用占位品牌名“曜识大模型”。
- 当前首版不接真实 API，所有演示能力以静态内容 + 前端状态切换呈现。
- 页面先做高质量首版，后续可继续替换成真实品牌内容。

## 素材 / API 策略

- 暂不依赖真实图片，避免无品牌资产时出现低质量占位图。
- 通过纯前端构图、渐变、网格和面板视觉模拟大模型工作台气质。
- 本版不调用远端 API，保留模板 API 运行时能力，后续如需接入表单或演示接口可继续扩展。

## 状态设计

- 已补齐并在页面内可见演示：
  - `Loading`
  - `Empty`
  - `Error`
  - `Active Feedback`
- 交互不依赖 hover 才能触达，状态切换在触屏设备上也可直接点击。

## 适配目标

- PC：双栏 Hero、错位区块、完整叙事节奏。
- Pad：保留主视觉层次，Hero 与能力区压缩为上下或 2 栏混排。
- H5：首屏优先露出标题、价值点、主 CTA 与一个关键工作台面板。

## 断点策略

- `>=1280px`：PC，大尺寸双栏与不等比分区。
- `768px - 1279px`：Pad / 小桌面，核心区块改为上下结构或 2 栏混排。
- `<768px`：H5，所有内容回落为单栏，保证标题、CTA、状态切换易点按。

## 设备使用场景

- PC：企业官网浏览、方案评估、内部分享。
- Pad：销售演示、会议现场浏览、横竖屏切换查看。
- H5：社媒跳转、微信内快速浏览、线索初步判断。

## 交互约束

- hover 只做增强，不承载唯一信息入口。
- 最小触控热区不小于 `44px`。
- Pad 横竖屏均采用安全重排，不保留复杂桌面悬浮结构。
- H5 首屏优先信息，不让装饰层挤占主要价值表达。

## 已确认结论

- 可基于合理假设直接完成首版。
- 页面采用静态单页实现即可完成第一轮官网交付。
- 当前重点是建立品牌调性与可信产品表达，而不是上线真实业务接口。
